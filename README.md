# Cell

面向科研工作者的可复用 Skill 集合：从选题、研究计划和文献综述，到论文模拟审稿、英文润色、科研绘图、投稿与返修，让每一步都基于真实材料、形成可继续使用的交付物。

仓库当前包含 **1 个总入口 + 12 个成员 Skill**。不知道该选哪个时，直接使用 `cell`；目标明确时，也可以点名对应成员。

## 项目定位

Cell 不是一组孤立的提示词，而是一套带有流程、参考资料、模板、脚本和验收规则的科研工作 Skill。每个成员只负责一个边界清楚的任务，总入口根据用户手里的材料、当前阶段和目标交付进行分流。

Cell 关注三件事：

- **先依据，后生成**：选题、计划、综述和投稿规则尽可能回到真实文献、用户材料或官方来源。
- **交付可继续使用的成果**：文档应可编辑，代码应实际运行，图片应真实返回，矢量图和 PowerPoint 对象应能继续修改。
- **不让模板覆盖研究差异**：区分事实、解释与推断，保护数据和作者判断，不用统一话术制造虚假的“专业感”。

## 快速开始

### 1. 安装

```bash
git clone https://github.com/yrui-cmd/Cell.git
cd Cell
python install.py
```

安装器会安装 `cell` 总入口和非插件成员。需要 PowerPoint 原生对象编辑功能时，再按[插件安装](#powerpoint-插件)完成 `cell-ppt-edited` 配置。

### 2. 新建任务

安装或更新后，重启 Codex 并新建任务，然后直接描述已有材料、当前问题和希望得到的结果：

```text
使用 Cell。我现在有这些材料：……
当前卡在：……
希望最终得到：……
```

不知道 Skill 名称时不必猜，`cell` 会选择一个最匹配的成员。已经知道目标时可以直接点名：

```text
使用 cell-manuscript-editing，在不改变科学事实的前提下润色这篇英文论文。
```

```text
使用 cell-visualization-code，按论文最终栏宽重构这段 MATLAB 绘图代码并实际验收。
```

```text
使用 cell_su7，把这张科研图重建为可编辑的 PowerPoint 图形。
```

## Cell 功能索引

下面列出仓库中的全部 Skill。适用场景用于选择入口；具体输入、平台、费用和完成条件以各成员的 `SKILL.md` 为准。

| Skill | 适用场景 | 不适用或边界 | 主要交付 |
| --- | --- | --- | --- |
| `cell` | 只知道当前科研问题、不确定该调用哪个成员，或任务需要在多个阶段之间正确衔接时使用 | 已明确点名成员时不替换用户选择；自身只负责分流，不能代替成员完成业务任务 | 选择并执行最匹配的成员 Skill |
| `cell-brainstorm` | 只有研究方向或初步想法，需要查新、判断知识缺口，并比较创新性与可行性时使用 | 已有明确题目并准备安排实施时改用 `cell-plan`；不用于写综述或直接执行实验 | 5 个带证据、研究方案和限制的选题论证 |
| `cell-plan` | 已有明确题目、投稿目标和实际条件，需要依据对标原始研究安排实验、分析顺序和时间时使用 | 不用于泛泛发散选题、只查文献或只写综述 | 基于 20 篇对标原始研究的研究执行计划 |
| `cell-review` | 需要围绕明确问题检索、核验并综合文献，形成完整批判性文献综述时使用 | 不用于单篇翻译、只找几篇论文、正文润色或选题推荐；启动前需确认参考文献篇数 | 一篇可编辑的完整 Word 综述，实际引用满足用户确认数量的经核验文献 |
| `cell-reviewer` | 已有综述或实验性/原始研究稿件，需要模拟同行评审、投稿前自审、证据核查和修订优先级时使用 | 不从零写综述、不直接替作者改稿，也不处理已经收到的审稿意见 | 有稿件定位和严重度依据的审稿报告、审后核查、综合判断与修订优先级 |
| `cell-manuscript-editing` | 已有英文论文需要语言、逻辑、证据强度和段落结构润色，或需要忠实转写作者已有中文研究内容；也适合减少模板腔并保持作者声音 | 不从零代写论文，不处理审稿回复、完整综述或投稿包；自然化不用于规避检测或隐瞒应披露的 AI 使用 | 保留事实、数据和作者判断的润色稿，必要时附关键修改说明 |
| `cell-reviewer-response` | 已收到编辑或审稿意见，需要归类问题、安排解决方案并按原顺序逐点回复时使用 | 未收到审稿意见时不启动；不把拟开展的实验写成已经完成，也不代替正文从零写作 | 第一阶段问题解决 Word；材料落实后生成正式 Response to Reviewers Word |
| `cell-submission` | 论文正文已经完成，需要按目标期刊整理格式、参考文献、图表、补充材料、Cover Letter、Title Page、声明和系统字段，或准备转投时使用 | 不从零写论文、不重做研究、不编造缺失材料，默认不代为点击正式投稿 | 经官方规则核对的完整投稿包 |
| `cell-visualization-code` | 需要生成、重构或审核 Python Matplotlib/Seaborn 或 MATLAB 绘图代码，统一多图风格，适配 IEEE Transactions、Elsevier 等版式，或检查最终物理尺寸、矢量导出和可复现性时使用 | 不用于反向复现某篇论文的数据图、机制示意图、图片编辑或描摹矢量化 | 实际运行过的绘图代码、必要输入或输入合同、样式 profile 和目标图件 |
| `cell-data-figure` | 有参考论文数据图，希望先用代码复现其视觉与结构，通过核验后再替换为自己的真实数据时使用 | 一般绘图代码任务使用 `cell-visualization-code`；不用于机制图、图形摘要、照片编辑或图片描摹 | 最终绘图代码、绘图前数据及 TIF/JPG/PDF 图件 |
| `cell_su7` | 已有科研图片或获准 SVG，需要重建为可继续修改的 PowerPoint 或 Adobe Illustrator 原生图形，并恢复可编辑文字时使用 | 不用于根据摘要从零设计期刊图，也不用于普通数据绘图；识别及可选处理可能依赖外部服务、凭据和额度 | 可编辑 PPTX 或 Illustrator 图形，以及必要的矢量中间结果 |
| `cell-cns-figure` | 有摘要、研究文字和可选参考图，希望通过小描两阶段流程生成“布局图 A → 高级设计图 B”，或查询该服务余额时使用 | 不用于路径识别、本地绘图或可编辑矢量重建；属于外部付费服务，每个阶段必须单独确认实时费用 | 已验证并下载的图 A、图 B PNG，或用户选择停在图 A |
| `cell-ppt-edited` | 需要快速批量修改已打开的 Windows PowerPoint 中的原生对象，包括填充、线条、字体、几何、组合、渐变、富文本和贝塞尔节点时使用 | 当前版本要求 Windows 桌面版 PowerPoint；不用于把位图重建成矢量图，也不支持 WPS/macOS PowerPoint | 保持文字、路径和版式可编辑的 PPTX |

## Skills 如何衔接

Cell 不要求从第一步走到最后一步。用户在哪个阶段遇到问题，就从对应成员开始；只有当前成果已经形成并且用户希望继续时，才进入下一阶段。

### 论文主线

```text
研究方向
  └─ cell-brainstorm → 明确选题
       └─ cell-plan → 研究执行计划

领域证据问题
  └─ cell-review → 完整文献综述

已有英文稿
  ├─ cell-reviewer → 模拟审稿与投稿前自审
  └─ cell-manuscript-editing → 内容与语言定稿
       ├─ 可再次使用 cell-reviewer → 核查修订后的证据与结论
       └─ cell-submission → 目标期刊投稿包
            └─ 收到真实审稿意见后使用 cell-reviewer-response → 修回回复
```

`cell-review` 可以在选题、计划或写作阶段独立使用，不是必须按顺序经过的流水线。`cell-reviewer` 只评审已有稿件，不自动代写、改稿或生成审稿回复。`cell-submission` 假定正文内容已经基本定稿；如果正文仍需重组、降结论强度或自然化，应先使用 `cell-manuscript-editing`。

### 绘图与 PowerPoint 选择

| 你手里的材料与目标 | 应使用 |
| --- | --- |
| 有数据或现有脚本，要编写、重构或规范 Python/MATLAB 绘图代码 | `cell-visualization-code` |
| 有一张论文数据图，要先代码复现，再换成自己的数据 | `cell-data-figure` |
| 有摘要或研究文字，要生成新的期刊设计图 PNG | `cell-cns-figure` |
| 有现成科研图片，要重建成可编辑 PPT/Illustrator 图形 | `cell_su7` |
| 已有 PowerPoint，要修改其中的原生文字、形状、路径或版式 | `cell-ppt-edited` |

每次任务默认只选择一个主成员。跨阶段衔接只传递已确认的材料、真实产物路径、版本、约束和未决问题；完成上一步不自动授权下一步，也不自动授权付费、上传或正式投稿。

## 安装与更新

### 非插件 Skills

`install.py` 默认安装到 `${CODEX_HOME}/skills`；未设置 `CODEX_HOME` 时安装到 `~/.codex/skills`：

```bash
python install.py
```

如果目标位置已存在任何同名 Skill，安装器会在复制前停止，避免出现半安装状态。确认要用当前仓库版本整体替换时使用：

```bash
python install.py --force
```

`--force` 只替换 Cell 的同名 Skill。若你修改过已安装副本，请先自行备份。

### PowerPoint 插件

`cell-ppt-edited` 是本仓库中的本地插件，不由 `install.py` 复制。安装非插件 Skills 后，在仓库根目录运行：

```bash
codex plugin marketplace add .
codex plugin add cell-ppt-edited@cell
```

该插件当前要求 Windows 桌面版 Microsoft PowerPoint。Windows 用户也可以使用它的[独立发布版](https://github.com/yrui-cmd/cell_ppt_edited/releases)。

### 外部服务与费用

大部分文本和本地代码流程不会主动提交付费任务。`cell-cns-figure` 使用外部两阶段期刊图服务；`cell_su7` 的识别及可选处理也可能需要外部凭据和额度。相关 Skill 必须在收费提交前展示实时余额、阶段费用或预计额度，并取得明确授权。安装、查询规则或读取文件不等于同意付费。

安装或更新完成后，请重启 Codex 并新建任务，以便加载最新 Skill 和插件配置。

## 为什么做 Cell

Cell 最早从科研绘图开始。AI 可以快速生成一张图，但科研交付还需要修改文字、调整路径、替换数据、核对版式，并把文件交给导师、合作者或期刊继续处理。一张只能观看、不能继续编辑的图，完成的是演示，不是完整交付。

早期项目 [`cell-lct`](https://github.com/yrui-cmd/cell-lct) 将参考科研图重建为可编辑的矢量路径和真实文字。这个过程也暴露了更普遍的问题：工具能够生成内容，并不代表内容适合当前研究。不同课题可能被塞入相似结构，不同机制可能被画成相似图，不同作者也可能被改成相似语气。

因此，Cell 把工作重点放在真实输入、任务边界和完成验收上：

- 选题要从可核验的知识缺口中形成；
- 计划要对应真实条件和对标研究；
- 综述要呈现证据之间的联系、分歧与限制；
- 论文润色要保护数据、科学判断和作者声音；
- 绘图代码要实际运行，并在最终物理尺寸下检查；
- 图片和文档必须真实生成、可打开，并尽可能保持可编辑；
- 投稿与返修不能编造材料、实验或完成状态。

我们的判断标准很朴素：文献没有核验、代码没有运行、图片没有返回、文件无法继续修改，都不能叫作完成。

## 仓库结构

```text
Cell/
├── skills/                    # cell 总入口及成员 Skills
├── plugins/cell-ppt-edited/  # Windows PowerPoint 本地插件
├── tests/                     # 仓库、安装器和路由测试
├── install.py                 # 非插件 Skills 安装器
├── requirements-dev.txt       # 免费、本地测试的公共依赖
└── README.md
```

不要只复制单个 `SKILL.md`。成员目录中的 references、assets、scripts、tests 和状态文件共同构成实际能力。

## 开发与测试

安装公共测试依赖并运行全仓测试：

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

这组测试不会提交付费任务或调用收费绘图接口。真实文献质量、科学判断、最终图片观感和桌面应用行为仍需使用实际任务验收。

`cell-visualization-code` 的 MATLAB 测试在设置 `MATLAB_BIN` 后会调用真实 MATLAB；未配置时跳过该项。`cell-ppt-edited` 的 Windows 运行依赖和专项测试位于 `plugins/cell-ppt-edited/`。

## 使用边界与许可

Cell 可以减少重复工作，但不能替科学作出承诺。它不保证论文录用或实验成功，不把未完成状态写成已经交付，也不假设第三方服务始终可用。文献、数据、软件、期刊规则和外部服务均以实际访问与运行结果为准。

除单独注明的第三方改编内容外，本项目采用 [MIT License](LICENSE)。`cell-reviewer` 包含基于 Apache-2.0 上游材料的改编内容，具体归属与许可见其目录中的 `NOTICE` 和 `LICENSE`。使用第三方文献、图片、数据、软件和服务时，还需遵守对应来源的许可、隐私和使用规则。

从你当前已有的材料开始即可：

```text
使用 Cell，帮我完成当前这项科研任务。
```
