# PPT 制作

## 你需要提供

- 演示主题。开头可选「默认」或「个性化」；有明确的使用场景、受众、时长或重点，可随主题一起提供。
- 相关资料，例如论文题名、DOI、链接或 PDF，项目资料、数据、图表或讲稿。
- 如有指定模板、参考样例、必用内容或固定页数，一并提供。
- 确认逐页安排和对应报价。

## 你会收到

- 供确认的《逐页安排.pptx》和报价。
- 《问答与原始资料.pdf》。模板预览并入 PDF；规划与模板 PPTX 仅供本地审阅。
- 等待面板中的排队位置、前方单数和订单进度；开始制作后按每页 15 分钟显示预计剩余时间。
- 最终交付的《成品ppt.pptx》，以及在 PowerPoint 编辑窗口中的成品预览。

## 内容完整与风格参考

逐页核对确认的内容、图证、实验状态、关键数字、条件和限制。流程图每一阶段都写清对象、方法、观测指标与状态。内容放不下时先缩小装饰、压缩空白、精炼重复文字，保留确认的内容与可读性。确需调整已确认的页数或内容范围，按原确认流程处理。

明确提供的风格图只取可见配色、字体和图形样式，画布和排版由实际结构模板或3号与正文布局库决定。风格图进入交接 PDF 模板区的独立风格参考页，普通资料图仍放资料区。文字风格说明只保留为问答记录。

## 已有成品快速重放

用户只要重新展示已有 PPT 时，不执行制作、余额、上传或接收流程。实际确认录屏选择后，直接运行 [本地重放](references/transfer.md#本地成品一条命令重放) 的 `replay.py`；脚本一次完成校验、副本准备、录屏、10 指针展示、保存及完成记录。不要逐步临时编写脚本，不提前手动打开待展示副本。

## 本机操作

0. 每次运行先按 [PPT API 配置](references/credentials.md) 检查 Skill 内的固定凭据入口并验证余额。首次使用或密钥失效时先完成配置，再继续问答、整理资料和提交。
1. API 配置就绪后，先提醒客户相关图片越充足越好，再按[选择模式](references/nodes.md#选择模式)呈现「默认（推荐）」和「个性化」。选默认就按已给要求及适合本次任务的默认值直接规划。只有选个性化才逐项实际询问，每次只问一项并给一个推荐。两种模式都要在上传前确认当前逐页安排和额度。
2. 核对客户资料。必用论文缺全文时，先从可访问的出版社、开放仓储等来源查找并下载全文，核对题名、版本和内容完整性。取不到时再请客户提供对应 PDF。原始文件只读。
3. 用[交接工具](references/handoff.md)生成并核对逐页安排、资料 PDF 和可选参考模板，交客户确认文件版本和额度。先整理 `outline.json`，默认必须包含首页（封面）、目录页和最后的感谢页，再安排正文；正文可按章节插入章节目录页或高亮当前章节的导航页，不限制整套只有一张目录。首页、总目录、正文中的目录及末尾感谢页都计入已确认的总页数与报价，不额外加页。只有用户明确要求省略或仅制作局部页面时才例外。规划稿页顶以醒目中文标注“首页 / 封面、总目录、章节导航、正文、感谢页”，不能只显示英文 kind 或在备注中说明。每页写清实际内容、故事展开、资料定位、版式、配色、证据、讲解时间和制作注释；文献资料标明参考编号、原文位置及图号/面板，不必在规划稿重复附文献图；自有资料应尽量完整附相关图片与图注，可放对应页后或集中到后面的资料区，并建立逐页对应关系。此阶段不调用生图。PDF 第一行固定写 `PPT 总页数：N 页`，N 为最终 PPT 内容页数，与内嵌索引一致；第二项注明模板选择。PDF 分区顺序为“问答 → 模板 → 资料 → PPT内容”，每个 PPT 内容页以 `# 第 N 页：标题` 开头。可选模板必须写入模板区，有模板文件时并入其实际代表页预览。按[内容与模板完整性](references/handoff.md#内容与模板完整性)逐页核对：已确认的内容、图表、图注和参考模板必须完整呈现；放不下时优先等比例缩小模板整体并调整布局，禁止为套模板删内容、裁切或遮挡。缩小后仍须清楚可读；PDF 可续页，正式 PPT 页数变更须重新确认。此要求同时写入 PDF 模板说明及受影响页的排版/制作注释。
4. PDF 发送到制作接口前，必须按[客户确认](references/handoff.md#客户确认)在聊天中列出当前 PDF 对应的大纲和每一页内容，标明 PDF 页码，展示文件链接、总页数及额度，并明确询问是否按这版大纲和逐页内容制作。等客户实际确认后，按[上传与等待](references/transfer.md)仅上传交接 PDF。以 PDF 首页声明的目标 PPT 页数作为报价依据，不按 PDF 物理页数计费；模板和资料页不另计额度。内嵌索引用于兼容和定位，存在时其 `page_count` 必须与首页一致；网站核对最终报价并在客户确认后扣费。上传并确认原订单已入队后，按[返回原对话](references/return-to-chat.md)启动绑定原对话和本订单的 Python 接收进程；禁止创建或恢复定时任务、heartbeat、cron 或 Windows 计划任务，再启动并打开聊天右侧进度面板。面板可访问后立即结束本轮聊天，最终回复只留「已上传，[查看进度](实际 progress_url)」。不得在聊天中继续轮询、等待制作完成、定时播报或运行守候代理。重试继续同一订单。
5. 后台只接收和校验成品。Python 收到并校验成品后只唤醒原对话一次，先单独醒目地问「要录下 PPT 的输出过程吗？」（需要录屏 / 不需要），留出空白并等实际答复。需要则先录制整个 PowerPoint 软件界面，不需要则直接按[PPT 输出规则](references/transfer.md#成品回传与-ppt-输出)输出。全部元素输出完成、可选录屏保存并核验后，确认接收进程已退出，在原聊天给出 PPT 和可选视频链接，最后单独一行写「感谢抖音：Cell-skills」。失败时报告真实问题，不能提前感谢或声称完成。

## 交付文件命名

最终交付保留输入 PPT 的原文件名，不添加随机编号、演示或修改版等后缀；录屏文件固定命名为 `ppt.mp4`，不使用 demo 或其他后缀。工作副本可使用唯一名称以避免 PowerPoint 窗口混淆，但不得将工作名称作为最终交付名称。成品保存到独立交付目录，不覆盖用户原文件。

## 内部演示规则

Windows 最终展示使用 10 个模拟指针并行分工（4 个图形、6 个文字）：图形搭建、中文先显示拼音再出现汉字、英文逐字显示，当前页全部完成后自动换页。先在文件关闭时隐藏预览副本的待展示元素，再打开编辑窗口；不先展示成品，不设置开场等待。图形与文字的原对象、组合、格式和层叠关系保持不变，播放中不反复删除对象或刷新层级；图片、SVG 和组合插图模拟粘贴：指针定位，短暂提示 Ctrl+V，整图一次出现；底框和线条直接显现。全部页的文字副本、指针和拼音框在预览窗口创建前准备并复用，辅助对象不放到画布外；窗口适配一次后锁定缩放。换页仅切换页面并驱动已备对象，禁止现场增删辅助对象或反复自动缩放。临时对象先隐藏，结束时统一清理；Office 短暂忙碌时有限重试。使用 [输出规则](references/transfer.md#成品回传与-ppt-输出)中的正式入口，不能用试验脚本替代订单完成记录。macOS 暂沿用兼容的逐元素展示，不声称具备未经实测的多指针效果。这些是后台执行规则，不向客户额外播报，不写入 PPT、规划稿、交接 PDF、页面备注或进度面板；仍须正常询问录屏选择，并报告必要的异常和完成结果。
