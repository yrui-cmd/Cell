# PPT 制作

## 你需要提供

- 演示主题。开头可选「默认」或「个性化」；有明确的使用场景、受众、时长或重点，可随主题一起提供。
- 相关资料，例如论文题名、DOI、链接或 PDF，项目资料、数据、图表或讲稿。
- 如有指定模板、参考样例、必用内容或固定页数，一并提供。
- 确认逐页安排和对应报价。

## 你会收到

- 供确认的《逐页安排.pptx》和报价。
- 《问答与原始资料.pdf》。模板预览并入 PDF；规划与模板 PPTX 仅供本地审阅。
- 等待面板中的预计时间、剩余时间和订单进度。
- 最终交付的《成品ppt.pptx》，以及在 PowerPoint 编辑窗口中的成品预览。

## 本机操作

0. 每次运行先按 [PPT API 配置](references/credentials.md) 检查 Skill 内的固定凭据入口并验证余额。首次使用或密钥失效时先完成配置，再继续问答、整理资料和提交。
1. API 配置就绪后，先提醒客户相关图片越充足越好，再按[选择模式](references/nodes.md#选择模式)呈现「默认（推荐）」和「个性化」。选默认就按已给要求及适合本次任务的默认值直接规划。只有选个性化才逐项实际询问，每次只问一项并给一个推荐。两种模式都要在上传前确认当前逐页安排和额度。
2. 核对客户资料。必用论文缺全文时，先从可访问的出版社、开放仓储等来源查找并下载全文，核对题名、版本和内容完整性。取不到时再请客户提供对应 PDF。原始文件只读。
3. 用[交接工具](references/handoff.md)生成并核对逐页安排、资料 PDF 和可选参考模板，交客户确认文件版本和额度。先整理 `outline.json`，每页写清实际内容、版式、配色、证据、讲解时间和制作注释；此阶段不调用生图。PDF 第一行固定写 `PPT 总页数：N 页`，N 为最终 PPT 内容页数，与内嵌索引一致；第二项注明模板选择。PDF 分区顺序为“问答 → 模板 → 资料 → PPT内容”，每个 PPT 内容页以 `# 第 N 页：标题` 开头。可选模板必须写入模板区，有模板文件时并入其实际代表页预览。
4. 仅在确认当前文件和额度后，按[上传与等待](references/transfer.md)仅上传交接 PDF。以 PDF 首页声明的目标 PPT 页数作为报价依据，不按 PDF 物理页数计费；模板和资料页不另计额度。内嵌索引用于兼容和定位，存在时其 `page_count` 必须与首页一致；网站核对最终报价并在客户确认后扣费。上传并确认原订单已入队后，按[返回原对话](references/return-to-chat.md)注册绑定原对话和本订单的心跳，保存真实自动化 ID，再启动并打开聊天右侧进度面板。面板可访问后立即结束本轮聊天，最终回复只留「已上传，[查看进度](实际 progress_url)」。不得在聊天中继续轮询、等待制作完成、定时播报或运行守候代理。重试继续同一订单。
5. 后台只接收和校验成品。成品返回后由心跳接续原对话，先单独醒目地问「要录下 PPT 的输出过程吗？」（需要录屏 / 不需要），留出空白并等实际答复。需要则先录制整个 PowerPoint 软件界面，不需要则直接按[PPT 输出规则](references/transfer.md#成品回传与-ppt-输出)输出。全部元素输出完成、可选录屏保存并核验后，停止本订单心跳，在原聊天给出 PPT 和可选视频链接，最后单独一行写「感谢抖音：Cell-skills」。失败时报告真实问题，不能提前感谢或声称完成。
