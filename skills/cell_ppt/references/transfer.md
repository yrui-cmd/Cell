# 固定 PPT 接口

上传前必须完成[客户确认](handoff.md#客户确认)：在原聊天列出当前 PDF 的分区、大纲和每页内容，收到对这一版内容及额度的明确确认，再核对 PDF SHA-256 与 approval.json 一致。没有实际答复时不得调用上传接口；不能先传 PDF 再询问是否按其内容制作。

固定地址 `https://xiaomiao-ai.com/api/ppt/v1`。由 Python 执行 `scripts/transfer.py submit 交接目录` 或 `status 交接目录`。客户端自动读取[已配置的 PPT 密钥](credentials.md)。

- `GET /health` 须返回 `ok: true`、`version: 2`、`job_modes` 含 `planned_deck`，且 `planned_upload` 声明 `files: ["material"]`、`format: "pdf"`、`billing: "declared_ppt_content_pages"`。不支持的契约先止步。
- `GET /balance` 查可用页额度。`POST /uploads` 只传 multipart `material`（交接 PDF），不传 `pptx` 或 `pptx2`。头为 `X-PPT-Job-Mode: planned_deck` 与已保存的 `Idempotency-Key`。客户端与接单程序读取 PDF 第一行 `PPT 总页数：N 页`；服务以该声明的目标 PPT 页数作为报价依据，每个目标 PPT 页 1 额度；PDF 的模板、问答、资料页及正文续页不增加计费页数。内嵌 `ppt-material-index.json` 用于兼容和定位，存在时其整数 `page_count` 须与首页一致；缺少索引的普通 PDF 由服务器按首页明确声明处理。网站沿用原报价、客户确认和扣费逻辑。
- 核对模式、PDF SHA-256、计费页数和金额。`GET /jobs/{job_id}` 查询同一单。只对当前 PDF 已获用户确认、报价完全相符的 `quoted` 调用 `POST /jobs/{job_id}/confirm`，传 `expected_page_credits`。确认即扣费入队。
- 采用绘图客户端的可恢复方式，在网络调用前落盘幂等键、原聊天、文件摘要及额度。重复运行复用原键或原 job_id。客户端不接受跳转至其他主机。没有订单号时重试原请求；已有订单号时使用同一订单。
- 入队后运行 `python -X utf8 scripts/transfer.py progress 交接目录`，将返回的 `progress_url` 用 Codex 的 `open_in_codex` 打开在聊天右侧。也可用同一命令重开原订单的面板。面板显示当前排位、前方单数、等待总单数（包含自己），不展示全站制作中单数。预计制作用时按已确认的目标 PPT 页数乘以 15 分钟计算，排队期间不倒计时；首次查询确认 `processing` 时记录开始时间并持久化到 `job-progress.json`，重开面板不重置。接口没有承诺制作开始时间字段，因此使用客户端首次观察时间，不以入队时间倒推。进度百分比是时间估算，不是真实页面完成率；超时继续显示等待，不能自动宣布完成。
- 面板由后台 Python 进程提供，每 5 秒串行查询原订单，沿用客户密钥。读取 `GET /jobs/{job_id}` 的 `queue.position/ahead/waiting/processing/as_of_unix`；`processing` 显示“制作中”，忽略排位；其他终态清空排队信息。查询失败保留上次结果并提示“状态更新中”，恢复后自动刷新；旧服务缺少 queue 时显示等待排位信息，不编造名次。制作完成后只接收、校验并保存成品，不启动 PowerPoint。绑定的 Python 接收进程在校验成品后一次性唤醒原聊天，询问是否录屏后再输出；感谢语只在原聊天完成输出时发送。暂时下载失败仍重试同一单。

## 上传后结束聊天

订单确认入队后，按[返回原对话](return-to-chat.md)启动绑定本订单和原对话的 `receive_and_wake.py start`，禁止创建或恢复定时任务。运行一次 `progress`，确认面板可访问并打开，随后结束本轮，只留「已上传，[查看进度](实际 progress_url)」。不在当前轮次循环等待。等待期间无变化不播报，成品返回或需要处理时才接续原对话。接收进程或桌面唤醒连接失败须如实说明，保留原单，不回退到定时任务。

## 成品回传与 PPT 输出

1. 后台仅接收和验证成品，Python 校验接收结果后一次性唤醒原对话。先问 **要录下 PPT 的输出过程吗？**，选项「需要录屏」「不需要」。问题单独展示并留白，必须等答复，不提前启动输出。按 [录屏及返回规则](return-to-chat.md)保存选择；需要录屏时先录制整个 PowerPoint 软件窗口并核验已开始。
2. 原对话运行 `python -X utf8 scripts/transfer.py play-elements 交接目录 --thread-id 原对话ID`。原订单号、结算状态、文件大小、SHA-256 和成品实际页数须与回执一致，单 PDF 不按报价页数拦截成品；旧单仍核对规划页数。保留回传原件，另建输出预览副本，不重复下载有效成品或再次收费。
3. 同一时间只运行一个输出工作进程，仅控制输出预览副本。Windows 默认由 `swarm_playback.py` 在桌面版 PowerPoint 编辑窗口展示：10 个模拟指针分为 4 个图形与 6 个文字任务，同时推进；中文显示拼音提示后出现汉字，英文逐字出现。文字等待对应底框出现后开始；保留原有字体、换行、组合和层叠关系，临时副本定位与原对象一致。所有待展示对象在打开前已隐藏，准备过程不显示成品，不加开场停顿。当前页全部完成后自动换页，用户手动换页时暂停原页任务并跟随选择，返回时继续；切到其他软件时暂停。结束或失败都清理临时对象，保存并核对内容、几何和原文件摘要；不能用“进程已启动”代替完成。macOS 暂沿用原 AppleScript 兼容展示（按视觉行逐元素显示），未提供多指针和拼音效果。新安装或升级先运行 `python -m pip install -r requirements.txt`，Windows 的拼音依赖缺失时明确报错，不静默切回旧效果。演示实现参数只用于内部执行，不写入客户内容。
4. 匹配本订单和本次运行的 `element-output-result.json` 明确 completed 后，若选录屏，保留末页约两秒、停止录制并验证视频。确认接收进程已退出，在原聊天提供 PPT、可选视频链接，最后单独一行写「感谢抖音：Cell-skills」。失败则停止录制、保留文件并如实说明，不发完成感谢语。


## 预览失败恢复

客户回来查询时，若日志显示预览仍在等待前台，先把当前 PowerPoint 预览窗口切到前台，并核验元素已开始输出。

成品下载成功但 PowerPoint 预览失败时，先查看交接目录的 `element-playback.log`。手动打开 PowerPoint 本身不会重启失败的工作进程；用 `python -X utf8 scripts/transfer.py play-elements 交接目录` 重试原订单预览，无需再次上传或扣费。客户端保留旧预览，创建新的预览副本；正在运行或已经完成的预览不会重复启动。

生成预览时，仅移除指向缺失或错误关系类型的非可视 custom tags 引用，保留原始回传文件及其摘要。其他无法打开的文件仍如实报告失败，不声称完整修复。错误日志保存 PowerPoint 的实际启动错误。

## 版本与接单端兼容

本客户端新建交接包仍在 PDF 中同时写入 `ppt-material-index.json` 和 `cell-ppt-handoff.json`，用于兼容和定位；两者内容一致，且页数须与首页明确声明一致。提交前核对页数、分区和摘要。不要仅修改首页文字来修复页数错误，也不要在用户确认后自动改 PDF 索引。旧包缺新索引时，在新目录重新构建并确认新 PDF 摘要和额度，保留原订单记录。已存在 job_id 的旧多文件订单仍按原文件摘要和原计费规则查询、领取，不转成新订单或再次收费。

本地派单仅接收这一份 PDF，不要求独立规划 PPTX 或模板 PPTX；参考模板应放在 PDF 内。若远端仍报旧输入兼容错误，保留原单，不回退上传多个文件或擅自重复扣费。

## 本地成品一条命令重放

已有成品无需查询旧接口。收到录屏选择后，直接运行以下命令；不要手工准备状态、反复打开文件或另写演示脚本。`--record` 必须来自实际用户答复，不能代选。使用已经安装本 Skill 依赖的 Python。

```powershell
python -X utf8 scripts/replay.py --source "D:/文件/成品.pptx" --record yes --response-source "用户回答：需要录屏"
```

不录屏时改为 `--record no --response-source "用户回答：不需要"`。已绑定订单优先用 `--order-root "交接目录" --thread-id "原聊天ID"` 替代 `--source`；从本地接收回执校验原订单与文件摘要，不访问 API、不扣费。每次重放建立独立目录，保留原订单和原件，使用同一正式输出工作进程和匹配 job_id/run_id 的完成记录。

脚本先以无窗口方式打开隐藏内容的副本，准备全部页的文字副本、10 个指针和拼音框，再创建编辑窗口；辅助对象坐标保持在页内，窗口适配一次后关闭自动适配并锁定缩放。换页期间不创建、复制或删除辅助对象，避免 PowerPoint 连续重绘和缩放闪烁。等目标窗口在前台、录屏实际采样后再展示。若提示切到 PowerPoint，直接激活该预览窗口即可，不重复运行。图片、SVG 和组合插图采用模拟粘贴：指针移到目标位置，短暂显示 Ctrl+V，再整体出现；不实际改动系统剪贴板，不重复复制/删除图片。底框、连线直接出现。10 个模拟指针同时推进；缓存文本属性和目标位置，不在每字刷新层级，不逐元素复制/缩放/删除图形。文字只改变临时副本的可见性，完成后恢复原对象，最后统一清理隐藏的辅助对象。Office 仅对明确忙碌/拒绝调用错误重试，最多 8 秒；其他错误直接报告。

结束核对 `element-output-result.json` 与当前运行一致，并验证 `recording-result.json`、视频可播放后再给出链接。录屏文件为新重放目录内 `PPT-output.mp4`，可编辑副本为 `PPT-replay-唯一标记.pptx`。

录屏从屏幕上 PowerPoint 完整窗口所在区域采集，按物理像素处理系统缩放；不使用可能只返回纯灰画面的窗口标题 GDI 抓取。窗口必须保持前台和位置尺寸稳定，变化则停止并保留部分视频。放行展示前先解码实际视频帧，完成后抽查开头、中间、结尾，拒绝纯色画面或全程不变的录制；`recording-result.json` 的 `pixels_verified=true` 及 `recording-pixel-check.json` 均通过后才能交付录屏，不能仅凭 MP4 文件存在或编码信息判定成功。
