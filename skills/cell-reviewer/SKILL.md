# Cell · 论文审稿人

从审稿人视角判断稿件的贡献、证据和结论是否成立。支持综述审稿人与实验性论文审稿人两条完整流程。Cell 是技能系列名称，不代表 Cell Press 官方身份，也不默认稿件投向 Cell；目标期刊由用户指定。

借鉴 Nature Reviewer 的独立审稿、证据定位、严重度校准及审后核查机制，新增综述分型与跨学科原始研究判断。工作流为本地实现，不是任何期刊的强制审稿格式。来源与标准边界见 [references/source-basis.md](references/source-basis.md)。

## 输入与分流

接收中英文全文、摘要、章节、图表、补充材料、参考文献及数据/代码说明。沿用已有输入；没有稿件时只索取正文或文件，不凭题目编写正式审稿。默认中文意见，用户指定英文或其他语言时服从。

先记录稿件版本、输入范围、可读性、目标期刊（未指定则使用通用科研标准）以及未提供的材料。按文章实际内容选择模式，标题中的 Review/Article 不是唯一依据。

| 模式 | 判断与必读参考 |
| --- | --- |
| 综述审稿人 | 以既有文献的解释、综合或证据整合为贡献；读取 [review-manuscripts.md](references/review-manuscripts.md)，再选叙述/批判性、系统、范围或 Meta 分析分支。 |
| 实验性/原始研究审稿人 | 以新实验、观测、计算、方法或数据资源为核心证据；读取 [experimental-manuscripts.md](references/experimental-manuscripts.md)。识别实际设计，观察性研究不得仅因属于原始研究而被称为随机实验。 |
| 混合稿件 | 综述加原始验证时按核心贡献确定主模式，对新增证据另用原始研究分支；不把 Meta 分析误判为需新增湿实验的论文。 |

只审摘要/局部章节或用户要求快速审阅时，默认一份范围受限的审稿意见。完整稿件默认三份相互独立的模拟审稿报告，再给一份综合意见；用户指定人数、篇幅、格式或不使用子代理时优先执行。接到审稿回复任务时转 `cell-reviewer-response`，从零写综述时转 `cell-review`；不得把审稿自动扩成写作、补实验或投稿。

## 证据和分级

每位审稿人均判断贡献增量、科学重要性、证据可靠性、适用范围、可读性；方法权重按稿件模式调整。期刊契合度与科学有效性分别评价。没有查新证据时写“相对现有文献的增量待核查”，不宣称“首次”“已被他人完成”。

每条实质性意见必须包含可核验观察、被影响的主张或元素、稿件位置、影响及最小充分修订。使用 `R1-M1` / `R1-m1` 等稳定 ID。具体字段见 [report-and-qa.md](references/report-and-qa.md)。

- **Major / Blocking Yes**：已定位的缺陷使中心结论无法成立，或核心有效性、伦理/数据来源问题妨碍可信评估。说明阻断的具体推断。
- **Major / Blocking No**：实质影响重要解释、证据范围或复现性，但不单独推翻中心结论。
- **Minor**：局部修正即可完成且不改变关键推断；不能标为 Blocking。
- **无法评估**：未提供、不可读或无法验证的材料是评估边界，不自动算缺陷。全文未报告可以评价其报告缺口，但不能据此断言实验未做或存在违规。

严重度按影响判断，不按修改成本或措辞强硬程度判断；没有问题的级别明确写未发现，不凑数量。重复单位、图例或统计方法即便只需补一句说明，若决定推断成立与否也可为 Major。

## 审稿执行

1. **准备固定材料包。** 将用户稿件、真实章节/图表定位、文件清单、评估边界及适用标准组成同一版本的输入包。保留原稿不覆盖。需要提取 PDF/Word 或辨认图表时用相应工具；OCR 不清处标为待确认。材料包不能含主审预判、疑点清单或统一结论。
2. **确定标准和证据边界。** 涉及当前期刊规则或文献新颖性的判断时，检索官方指南/原始论文并核实。引用只能支持实际读到的内容，只有摘要时注明。公开检索使用去标识化主题词，不把未公开稿件正文、敏感数据或完整未公开标题提交给外部服务。不能联网时保留稿内评估，列明外部判断尚未核验。
3. **预先设定侧重点。** 按模式参考文件为 R1/R2/R3 指定不同重点，但每人仍覆盖共同评价轴。若核查了公共资料，在开审前将同一中性证据摘录及链接提供给所有审稿人；不得让不同证据访问权限制造分歧。
4. **独立生成报告。** 多审稿人必须使用各自全新上下文，子代理用 `fork_turns="none"` 或等效隔离。只传相同材料包、技能与对应参考文件、输出规范、该审稿人的重点和专属输出位置。明确限定只读这些输入及自己的文件，不读取其他报告或主审工作记录，不再生成其他审稿人。子代理不得继承含其他审稿结果的历史。主审不下发问题清单，也不设重复率目标。没有隔离能力时给单报告，或按用户要求明确标注“多视角、非独立审稿”，不声称互盲。
5. **定稿后再比较。** 每位审稿人先完成本报告事实和定位自检，再冻结报告。随后主审读取 [consistency-audit.md](references/consistency-audit.md)，对适用项目独立核查，最后按 [report-and-qa.md](references/report-and-qa.md) 汇总。单报告也做适用的核查；没有数据可算时记录无法评估，不伪称通过。
6. **汇总与交付。** 至少两份独立报告提出同一底层问题才称“共识”；只有至少两份均判 Major 且 Blocking Yes 才称“共识阻断问题”。严重度不一致时保留分歧。审后发现单列 `AUD-01` 等，不能冒充审稿共识。不得为制造差异改写冻结报告；若发现报告事实错误，保留原版本并附勘误，取消错误意见对共识的支持。

## 输出和完成

完整稿件默认输出审稿设置、逐位报告、审后核查、综合意见及修订优先级；一人审阅不输出虚构共识。具体结构、意见字段和交付检查见 [report-and-qa.md](references/report-and-qa.md)，生成报告前读取。

默认使用可阅读的 Markdown；按用户要求交付 Word/PDF 时使用相应文档能力并检查成品。长报告保存到当前工作区 `output`；最终链接用户可见的真实文件并给出目录。内部缓存产物先复制到交付目录并校验一致。

建议可为“证据支持较充分”“小修”“大修”“当前证据不足以支持发表建议”或“材料不足，暂不判断”，并给稿件内依据；这是模拟审稿立场，不是编辑决定。修订建议按“关键修复、重要增强、局部改进、可选扩展”组织；可选扩展不作为接收条件。不代写作者回复，不承诺接收率，不替用户上传或提交。
