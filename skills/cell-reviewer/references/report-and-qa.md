# 报告结构与交付检查

报告先给中心判断，再展开证据。短任务压缩篇幅，完整任务保留不同报告和意见来源；不以表格或固定条数代替推理。

## 审稿设置

标明稿件版本/范围、主模式及子类型、目标期刊或通用标准、报告语言、已读取材料、缺失/不可读材料、外部核查范围、实际审稿人数及隔离情况。模式尚不明确时说明暂按什么审，以及这会影响哪些判断。

## 每位审稿人

1. 总体评价：忠实概括核心贡献、适合的读者及当前证据支持程度。
2. 主要优点：限于实际可见内容，不机械平衡正负意见。
3. Major Concerns：逐条列证据、影响和验收标准。
4. Minor Comments：局部可执行修正。
5. 综合建议及置信边界：区分科学有效性、重要性/期刊契合度、仍无法评估的部分。

### Major 意见字段

| 字段 | 内容 |
| --- | --- |
| ID / 分类 | `R1-M1`、Major、Blocking Yes/No 及理由。 |
| 位置 | 已核验章节/段落、图/表/补充项；没有页行号时用标题和短引文，不能编造。 |
| 主张/受影响元素 | 忠实转述被挑战的结论、方法或报告内容。 |
| 证据与问题 | 材料中的具体观察，证据来自稿件、核查文献还是缺少报告。 |
| 影响 | 为什么改变可信度、解释、复现或关键结论；区分已证明和待核实。 |
| 最小充分修订 | 需要什么澄清、复算、证据或结论调整；可替代路径确实能修复同一问题时给出。 |
| 验收依据 | 怎样判断该问题已解决，而不是泛泛要求“加强讨论”。 |

Minor 使用 `R1-m1`，写位置、问题及具体修正；不必重复所有 Major 字段。没有该级意见写“从所提供材料中未发现可证实的问题”。

## 综合意见

- 将同一底层问题映射为 `S-01` 等，并保留各报告原始 ID；意见相似不等于相互独立。
- 两人以上独立提出才称问题共识；严重度或阻断性分歧要写明。共识不证明意见必然正确，少数的关键证据也不能按票数丢弃。
- 分开列共识优势、共识阻断问题、其他主要问题、单一审稿人的重要意见，以及真实的判断分歧。
- 单独列审后核查 `AUD`，注明已证实、待核实或无法评估，不回写冻结报告。
- 修订优先级表按“关键修复、重要增强、局部改进、可选扩展”排列，包含关联 ID、动作、验收条件；不虚构作者已经完成修改或所需确切工期。
- 最后交代未获支持的中心主张、待补输入和当前建议。不把模拟建议写成期刊决定，不估计无依据的接收概率。

一位审稿人直接给个人结论、核查和优先级，不输出共识或虚构 R2/R3。用户只要一份合并报告时可合并展示，但如声称独立评审，后台仍须真实隔离并保留来源；用户限制不使用子代理时改为单报告或注明非独立多视角。

单人场景可以由同一代理在定稿后复查，但应明确是“同一代理的第二轮核查”，不能称为另一位审稿人或独立验证。只有评阅材料未显示某项内容时，先列材料边界；只有确知相应完整部分已提供且应在其中报告，才评价稿件报告缺口。

## 完成前核查

- 类型是否选对：叙述性综述未被强制系统综述化，Meta 分析未被要求补湿实验；实验设计检查与主张相关。
- 相同输入版本是否送达所有独立审稿人；是否使用新上下文且未读其他报告/疑点；失败或缺席的审稿人是否如实披露，未伪造三人报告。
- 重要意见是否有实际位置、事实依据和最小充分修订；不把材料缺失认定为没做实验、失当行为或无创新。
- Major/Minor、Blocking 和修订类别是否与影响一致；可选扩展不能伪装成阻断条件。
- 审后核查是否只报告实际做过的检查，算术证明与可疑模式是否区分。
- 共识是否可回溯至少两份独立意见；单人关键意见和严重度分歧是否保留；冻结后事实错误是否透明勘误。
- 参考文献、DOI、图号、实验细节、审稿人身份和期刊规则是否均未杜撰；报告规范是否与方法学质量评价区分。
- 最终文件是否可打开、无截断；若复制交付，源文件与交付副本是否一致。PDF/Word 的版面核查按相应文档能力执行。
