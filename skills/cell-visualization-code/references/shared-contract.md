# 共享代码合同

## 输入与科学含义

绘图代码只消费明确声明的文件和字段。读取后检查列名、类型、单位、非有限值、重复键、分组、顺序和必要的唯一性。不得凭字段名猜单位；不得把技术重复、细胞、视野或时间点自动当独立样本。

预处理与绘图分开。确需在同一脚本执行的过滤、聚合、归一化或变换，应使用命名函数和显式参数，并在导出的绘图前数据或运行记录中保留前后数量。不得根据图是否更显著决定排除规则。

只有汇总数据时，画汇总估计及其已知不确定性；不重建虚假个体散点。统计标注来自当前输入重新计算或经核实的输入字段，不把星号本身当统计结果。

## 代码结构

推荐结构是 `load → validate → compute → draw → export → main`，允许后端惯用的等价组织。核心要求是数据逻辑、视觉样式和文件导出可分别检查。

- 一个项目使用一个共享 style/profile，避免每张图复制略有差异的常量。
- 科学映射使用有意义的变量名，不用散落的列号、魔法索引和无注释常数。
- 输入、输出和 profile 通过参数传入；默认路径相对于脚本或明确的项目根目录解析。
- 正式代码不联网下载数据、不训练模型、不调用生成式图片服务。
- 失败时返回非零状态或抛出可见错误，不生成看似成功的空图。
- 重跑不得覆盖原始输入；是否覆盖已有输出由用户任务或显式参数控制。
- 运行环境版本、随机种子和影响结果的库参数记录在内部审计信息中。

## 视觉语义

先定义角色，再选择颜色和线型。例如 observation、proposed、baseline、reference、limit、uncertainty。项目内同一角色保持一致；模型比较图中同一模型跨图保持一致。

比较面板共享可比较的轴范围、变换、归一化和色标。热图比较使用同一矩阵定义、顺序、`vmin/vmax` 和色图；相关矩阵可能为负时使用以零为中心的发散色图。

主曲线、次要曲线、参考线、场景集合和网格形成稳定层级。网格在数据下方；区间填充不遮挡主曲线；阈值线不得与主要数据使用无法区分的编码。

面板字母、变量名、模型名、单位和图注术语必须与正文一致。不要在绘图脚本中静默修改大小写、连字符或缩写。

## Profile 的性质

Profile 是项目或期刊配置，不是普遍科学规范。字体、栏宽、DPI、格式和颜色空间以当前正式要求为准；范文中观察到的样式不能冒充期刊硬性要求。

更换期刊模板时保留科学映射和相对层级，重新测量栏宽、最大高度、最终字号、格式、分辨率、颜色空间和字体要求。不同投稿 profile 的输出保存在不同目录，不覆盖已批准版本。
