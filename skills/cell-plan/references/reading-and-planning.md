# 阅读、任务与时间安排细则

按需读取本文件，不必每一步重复加载。它补充SKILL.md，不改变“直接替用户安排研究”的主任务。

## 1. 搜索与核验

把主题拆为研究对象、核心因素、结果、方法/模型四组关键词，并用同义词和必要的中英文名称扩展。先检索一批候选，例如约40—60篇，再依据关联度决定是否继续；不是以搜索返回数量代替阅读量。

期刊范围与科学相似性共同考虑。原始研究类型应相称；方法论文只证明方法的适用条件，不证明本研究的实体结论。综述帮助定位原始来源，必要的报告规范和期刊作者指南单独保存，不挤占20篇。

每条书目信息由出版者、论文正文或权威文献数据库核验。优先DOI；无DOI时使用稳定论文URL/其他唯一标识。确认正式版、勘误和撤稿信息，不把撤稿研究作为可靠依据。预印本和正式版属于同一工作，只按一篇计数。

检索范围放宽顺序：同问题→同模型/方法→同证据要求的相邻研究。扩大时记录用途，不牺牲基本相关性。全文获取可使用出版者开放页、公开仓储、合法作者稿或用户有权提供的文件；不得虚构机构登录或绕过授权。

## 2. 全文完成的含义

状态只使用下列四类：

- `metadata`：只查到题录。
- `abstract`：只读到摘要。
- `partial`：有正文，但正文/主图/相关方法/核心补充中的必要部分尚未读取。
- `full`：正文、主图与图注、相关方法、必要核心补充均已读取。

没有发布补充材料且核心证据完整，可将补充状态记为 `not_needed`，并写原因。存在相关材料但无法获取必须记为 `unavailable`，不能写 `not_needed`。`full`不是阅读全文的自我声明，需要有实际工具读取和来源定位支持。

HTML可优先阅读正文与嵌入原图；PDF按章节连续读取，必要时渲染主图/表页。视觉内容不全时不从摘要或图注猜实验结果。保存书目和少量自己的概括，不在交付中复制整篇受版权保护的全文。

## 3. 每篇的紧凑记录

记录文献ID、核实来源、版本、用途、阅读状态和访问日期。用紧凑条目保存：

1. 研究问题与主要结论，区分相关、因果、预测、机制等结论范围。
2. 每张主图回答的问题，例如“Fig.2：比较X与Y条件下的主要终点”，不抄图注全文。
3. 决定性设计、关键对照、独立样本单位、方法条件和局限。
4. 精确证据定位；涉及同一文献多个关键结论时分别保留定位。
5. 对计划的影响：采纳哪一设计、删掉哪一工作、增加哪个对照、调整哪个顺序；或者“用于背景定位，不增加实验”。

在5/10/20篇的内部整理中，只更新待补文献类别和任务变化，不重写一遍所有笔记。来源版本变化或发现错误时重新打开原材料核验。

## 4. 不同研究类型的任务具体化

不要把下面内容全部叠加；只采用与课题相关的维度。

**实验研究**：材料/模型、干预与对照、独立重复单位、主要读出、测量方法、必要质量控制、分析方法及开始条件。剂量、处理时间等数值需有文献或本地SOP依据，无法确定时把参数预实验安排成第一批任务。

**队列/临床观察研究**：目标人群、样本来源、暴露和结局定义、随访、混杂变量、缺失数据、分析集和主要统计模型；不能把预测、关联和因果混写。涉及实际受试者或医疗干预的任务须以适用审批和专业管理为前提。

**组学/单细胞研究**：样本级设计、质量检查、批次和混杂、注释依据、比较单位、重复与验证数据；不能把海量细胞当作海量独立患者。选择方法时核查当前原始论文/官方文档，并写明方法适用条件。

**机器学习/计算研究**：数据版本、标签、训练/验证/测试拆分单位、防止信息泄漏、基线、主要指标、消融或稳健性测试、独立验证、计算资源。不能把测试集反复用于选模型。

**工程/方法/理论研究**：目标问题、假设或工作条件、基准/对照、推导或实现任务、误差/性能指标、复现条件和适用边界。不强行增加生物医学机制验证。

每个数值标明属于已核实值、参考范围、规划估算或待确定参数。计划越具体，不代表未核实数值越多。

## 5. 时间安排规则

先写任务和依赖，再写时间。估算应考虑准备、执行、分析、重复确认、设备/样本等待和人员能力，不只填写操作本身的持续时间。

近期按周，较远阶段用时间区间和启动条件。若日期未定，可写“关键预实验稳定后第1—2周”，同时在排程元数据中保留估算窗口和先决条件，不能假装它已承诺完成日期。

没有预算报价就不报精确采购总价。若给出估算，应写币种、来源/假设和范围。启动前需确认的资源要有核实动作、相对时间以及不可获得时的具体替代安排。

为核心任务写“完成标准”和“路线调整条件”：例如先核实数据质量/测量可靠性，再判断观察结果；不得将统计显著性当作唯一成功标准。不能以增加方法和数据量替代回答原始问题。

字段规则：
- `reading_status`：`complete` 或 `partial`；`partial`只能保存在内部续做，不能通过正式交付检查。
- `target_paper_count`：默认20；其他值必须有 `target_count_instruction`，记录用户明确改变篇数的原始指令来源。不得为通过检查自造用户指令。
- `limitations`：内部材料或条件记录；不要求因阅读不足填写“限制说明”，不自动输出到计划。
- `open_skill_tasks`：尚未完成的检索、阅读、核验、选线与排程任务；正式交付前必须为空。实验室将来执行的研究任务写在 `tasks`，不要写入此字段。
- `design_review`：正式交付必须存在。`applicability` 为 `required`、`not_applicable` 或草稿期的 `undetermined`；正式交付不能保留 `undetermined`。不适用时给出课题相关理由并令 `designs=[]`；适用时至少有一个设计对象，并用 `task_ids` 关联实际任务。
- `resource_review`：正式交付必须存在。适用时用稳定资源 ID 记录人员、设备、设施、外部依赖或关键材料，并让任务 `resources` 和 `allocations` 对应这些 ID；不适用时给出项目相关理由并令两个数组为空。
- `capacity` 与 `unit`：容量已知时写正数及可比较单位，如 person_hours_per_week、slot_per_week；未知写 `null`，不得默认无限。多个任务在未知容量资源上重叠时，必须先核实，或在 `overlap_resolution` 写明实际确认依据。
- `allocations`：记录任务实际投入窗口和每单位时间用量。`occupancy` 为 `active`、`exclusive` 或 `passive_wait`；被动等待只有在真实占用设备/人员时才令 `holds_capacity=true`。脚本只发现明确的超容量和未知容量重叠，不声称求得最优排程。
- `experimental_unit`、`observation_unit` 与 `analysis_unit`：分别记录独立接受处理/进入比较的单位、产生单次观测的单位以及主要推断的分析单位。三者可以不同，但必须用 `independence_basis` 说明层级、汇总或聚类处理，不能把同一样本的技术重复当作独立样本。
- `assignment`：只取 `randomized`、`nonrandomized`、`observational` 或 `not_applicable`。随机分配必须保存 `randomization_record`，说明方法、种子或分配表位置；其他类型用 `assignment_rationale` 说明原因，不能为了过检查假写随机化。
- `blocking_factors` 与 `known_confounders`：均为字符串数组，可为空；是否为空都要用 `blocking_rationale` 写明本课题的核查和处理方式。`blinding`、`batch_run_order`、生物/技术重复、样本量依据与排除/停止规则使用可执行描述，不只写“已考虑”。
- `read_receipts`：正文、全部主图、方法和必要补充的实际读取凭据数组。核心补充为 `read` 时必须有其凭据；`not_needed`时保留依据即可。
- `evidence_file`：相对于状态文件目录的UTF-8笔记路径，限定在该目录内部。每篇独立笔记至少包含 `## 原文定位`、`## 主图`、`## 方法`、`## 补充材料`、`## 对计划的影响` 五节，各节有实质内容；同时记录真实文献标题与来源。正文、图表与方法必须根据实际已读材料记录。
- `work_id`：同一工作的预印本与正式版共用标识；`source`保存核实后的真实来源，不能靠不同URL重复计数。
- `article_type`：`original`、`preprint`、`review`、`other`。默认核心计数只纳入 `original`。
- `counted=true` 的论文必须 `read_status=full` 且必要部分已完成；`not_needed` 要说明原因。
- `basis`：`literature`、`user_data`、`design` 或 `operational`；后两者仍需在 `basis_note` 中写具体安排理由。
- `source_ids`：对应已记录文献，允许一任务引用多篇；仅作候选或未读到关键材料的来源不得支撑确定的方法参数。
- `depends_on`：必须先完成的任务ID。以完成→开始依赖解释；允许同一周前后衔接，但正文必须写清顺序，不代表完全并行。
- `priority`：`must`、`conditional` 或 `optional`。`conditional` 与 `optional` 均应在 `condition` 写何时开展；已触发的工作更新为 `must`。
- `start_week`/`end_week`：正整数估算窗口；实际判断同时考虑条件与资源。可选任务不能暗中成为必做任务的先决条件。

内部结构检查：

```bash
python <技能目录>/scripts/check_plan.py <任务目录>/_work/plan_state.json --mode draft
```

正式交付检查：

```bash
python <技能目录>/scripts/check_delivery.py <任务目录>/_work/plan_state.json <任务目录>/_work/研究执行计划.draft.md
```

`draft`模式只用于续做检查，`delivery_ready`始终为false；不能将其返回码0解释成可以交付。`check_delivery.py`要求完整阅读、规定计数、有效状态与依赖、没有未完成Skill任务、实际存在的证据文件、读取凭据以及清洁的计划文本。正文必须引用计入对标的文献，不能有引用表之外的悬空编号。

脚本在本地检查记录与文件；宿主还须逐项对照真实读取、来源定位与任务依据，不得用自填布尔值代替阅读。检查日志及这些内部技术说明不进入最终研究计划。

## 7. 完成不足时继续做，不追加免责说明

单篇全文或关键补充无法读取：优先合法全文页、公开仓储、作者稿和用户有权提供的资料；仍失败则换一篇用途相当的合适研究。保留最接近但未读文献的候选记录，不把它当不存在，也不拿它支撑未经核实的方法。关键近期证据不能通过换一篇无关论文跳过。

摘要提示了会影响核心路线的新证据：先获取正文并核查，把判断落实到安排中。不要在成稿写“尚未计入”“开始实验前再核对”。文献核查由Skill完成；仪器适配、试剂性能或剂量可行性等本地预实验才由研究者执行。

完成篇数不足：返回阅读，不能因为已有计划正文就收尾。只有真实外部阻塞才启用SKILL.md规定的暂行稿路径，并用一句事实状态说明区别于正式交付，不附大段解释。

## 8. 最终文本检查

删除对象是无助于安排的模型自述，例如“本次交付只是研究安排”“尚未执行细胞/动物/患者实验”“未分析用户原始数据”“结构检查不能替代科学验证”。不要把这些句子换一种说法继续保留。

必须保留研究本身的事实与依赖，例如“完成伦理审批后开始入组”“该比较尚不能区分两个解释，因此安排X对照”“剂量范围由参数预实验确定”。这些是计划内容，不是免责声明。

先解决工作缺口，再去除过程性文字；不得将删除限制段落作为隐瞒未完成工作的手段。脚本的文本扫描只是一道检查，宿主还须按含义复核，防止同义改写漏检。
