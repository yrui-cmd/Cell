# Cell · 论文 PDF 原位翻译

把用户有权处理的英文科研论文 PDF 转成中文阅读版。默认保留每一源页的物理尺寸、方向、宽高比、页面边界、分栏和图表位置；只有用户明确要求时才统一为 A4。主要产物是图片型 PDF，不承诺可搜索文字、可编辑排版、像素级复刻或人工认证译文。

## 路由边界

- 本 Skill：英文论文 PDF → 保留版式的中文图片型 PDF。
- `cell-manuscript-editing`：修改作者已有英文稿，或把作者已有中文研究内容忠实写成学术英文。
- `cell-review`：从零检索、综合和撰写完整文献综述。
- 普通文字翻译、逐句双语对照或可编辑 Word 译稿不自动使用本 Skill。

用户拟公开发布译文时提醒其确认论文版权和翻译/再发布许可；私人阅读任务不擅自扩大为公开分发。

## 输入与交付

- 输入：一个英文科研论文 PDF；可选实际 PDF 页码、术语表、已确认译文、保留原文列表及 A4 要求。
- 页码从 1 开始，按 PDF 实际页序解释；未指定时处理全文。只有文件不明确、页码越界或范围歧义会改变产物时才询问。
- 默认输出一个中文图片型 PDF，按源页顺序排列。内部任务账本、逐页 PNG、提示词快照和质量检查报告不交付，除非用户明确索要。
- 图片生成属于概率性页面编辑。数字、单位、公式、引用、图表数据和细小文字存在生成误差风险；质量检查能发现明显问题，但不能等同于逐字人工校对。

## 按需读取与依赖

- 首次生成前读取 [单页翻译提示词](references/image-translation-prompt.md)。
- 每页结果生成后读取 [逐页质量检查](references/quality-review.md)。
- 使用 [页面任务脚本](scripts/pages.py) 渲染源页、锁定提示词和结果、记录检查并封装 PDF；脚本不调用模型。
- 本地需要 Python 3.9+、PyMuPDF 和 Pillow。默认使用用户指定环境；本项目约定使用 Conda `dl`。

## 执行流程

### 1. 建立不可覆盖的任务

保留源 PDF，只在独立任务目录工作。续跑复用原任务目录，不清空账本或为绕过次数限制新建同一轮目录。

```bash
"$PYTHON" "$SCRIPT" prepare --pdf "$PDF" --pages "$PAGES" --work-dir "$JOB"
"$PYTHON" "$SCRIPT" status --work-dir "$JOB"
```

`PAGES` 为 `all` 或如 `1-3,5` 的实际页码。脚本默认以 240 DPI 渲染源页。将本次通用提示词及用户术语约束保存为 `$JOB/generation-prompt.md`；续跑不覆盖。来源 PDF、页面图片、提示词快照和已记录结果发生变化时停止，不继续使用失配账本。

### 2. 逐页生成并绑定结果

每页先用 `view_image` 查看源页，再 `reserve`；预留成功后立即用宿主内置图像生成/编辑工具处理该源页。只传当前页的原始页面图，使用不透明白底；提示词正文必须与 `reserve` 保存的快照一致。

```bash
"$PYTHON" "$SCRIPT" reserve --work-dir "$JOB" --page "$PAGE" --purpose initial --prompt-file "$PROMPT"
# 调用一次图像编辑能力，保存其明确返回的结果。
"$PYTHON" "$SCRIPT" record --work-dir "$JOB" --page "$PAGE" --attempt-id "$ATTEMPT_ID" --image "$IMAGE"
```

同一翻译轮次每页只有一次生成机会，最多使用 `status.policy.max_in_flight` 个未结束请求；不要提前预留全部页面，不使用子代理承载生成调用。结果不明时等待或找回原调用，不能重复提交。工具整体不可用时停止新提交并保留已有状态。

### 3. 逐页检查而不伪造准确性

对每个已记录页面，用 `view_image` 分别查看源页和中文页，按质量参考检查内容区域、数字/单位、公式、引用、图表数据、版式和可读性。把实际观察写成 JSON 后登记：

```bash
"$PYTHON" "$SCRIPT" review --work-dir "$JOB" --page "$PAGE" --attempt-id "$ATTEMPT_ID" --review-file "$REVIEW_JSON"
```

状态只可为 `pass`、`issue` 或 `unknown`。`pass` 表示在实际检查范围内未见明显问题，不表示逐字准确；无法辨认的细小文字、公式或图表标签用 `unknown`，不能猜测。发现问题用 `issue` 并准确写页码和区域。质量检查不得修改账本或虚构第二次生成。

### 4. 封装与交付

所有已提交请求先收尾。正常封装不使用 `--pdf-only`，让脚本要求每个采用页面已有质量登记；生成的 `_逐页检查说明.md` 只作内部审计：

```bash
"$PYTHON" "$SCRIPT" assemble --work-dir "$JOB" --output "$OUT"
```

只有用户明确要求统一 A4 才增加 `--a4`。脚本按源页物理尺寸等比例居中嵌入图片，不裁切、拉伸或添加 OCR 层，并复核 PDF 可重开、页数、页面尺寸和嵌入图片。

- 全部采用页均为 `pass`：交付中文 PDF，同时说明它是经逐页视觉检查的阅读版，不是人工认证译文。
- 存在 `issue` / `unknown`：仍可生成供查看的检查稿，但不得称完整准确；交付句列出受影响原页码。用户明确要求更新这些页时，使用带授权记录的新 overlay 任务，只重做指定页并重新合并。
- 有缺页：只有用户接受部分结果时使用 `--allow-partial`；文件名必须保留脚本添加的 `partial` 标识。所有页均无可用结果时不生成空 PDF。

正常最终回复只链接一个真实 PDF，并用一句话说明完成状态或受影响页。不要附逐页 PNG、JSON、提示词、技术日志或内部检查报告。

## 异常与续跑

以 `task.json` 和 `status` 为准，不手工改状态：

- `reserved` / 结果不明：继续等待或找回原结果。
- `failed`：该轮机会已使用；原调用的结果后来可用时，按原 attempt ID 补录。
- `recorded`：复用不可变结果，不覆盖。
- `recoverable_output`：按状态提供的确切路径和原 attempt ID 执行 `record`。

确认原调用已结束且没有结果时才执行 `fail`。发布收尾中断时，对 `status.pending_assemblies` 中的原路径重跑相同 assemble 命令；脚本只恢复与当前账本完全一致的文件。

## 完成条件

- 源 PDF 未覆盖；选定页、页序、源页尺寸和方向正确。
- 每个采用页面都绑定唯一结果、提示词快照和实际质量登记。
- 明显的内容缺失、数字/公式/图表变化和版式破坏已标出，没有用 `pass` 隐藏未知。
- PDF 已真实生成、可重开、页数与映射一致；部分稿与检查稿没有冒充完整译文。
- 最终只交付用户要求的 PDF，版权边界、生成式翻译限制和未解决页面如实说明。
