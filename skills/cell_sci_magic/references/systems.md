# 内置术语与问事知识

## 一、先分清问题属于哪一层

历法解决“哪一天、哪个时段、是什么日时标签”；传统择日解决某一用事的民俗宜忌；本包评分解决候选窗口如何按固定规则排序。这三层都不等于预测编辑决定。

| 概念 | 内置解释 | 在本包中的用途 |
|---|---|---|
| 公历、农历、干支 | 不同的日期表达与循环标记；天干十位、地支十二位按规定组合 | 由实际历法数据产生，不能凭印象填日期 |
| 阴阳五行 | 阴阳及木、火、土、金、水的传统关系语言 | 概念问答；不因临时声称“文章属木”而改分 |
| 八卦与六十四卦 | 由阴阳爻构成的卦象系统 | 可解释用户明确给出的卦象；没有起卦过程就不说得了某卦 |
| 四柱八字 | 以出生年、月、日、时的干支组织个人命理解释 | 个人入口实排四柱，含旺衰/格局/取用候选及大运模型；复杂格局不强判 |
| 通书择日 | 按具体事项读取日宜忌、日值与时值 | 当前实际使用的主线 |
| 奇门遁甲 | 在特定排法下组织宫位、门、星、神等符号 | 本包只做概念解释和已确认盘面的有限解读，不运行完整排盘 |
| 六爻、梅花易数 | 按各自起卦方式围绕具体问事解释 | 不将即兴文学取象混入投稿日期评分 |
| 紫微斗数 | 需要独立排盘规则的个人命理系统 | 不把未计算的命宫和星曜写入结论 |

术语只按其所属体系使用，不能把多个体系堆在一起当成更准确的证明。本任务方法依据在 `sources.md` S1—S5；本表用于限定解释范围，不作为额外评分公式。

## 二、报告中的通书术语

**用事**：要完成的具体事件。投稿、修回、基金提交均采用“上表章”的现代类比，不为三个入口编出三套不同基础分数。

**日宜忌**：指定传统事项是否出现在所用历书的最终宜或忌中。必须读取完整综合结果；明确列忌或宜忌冲突时，不推荐该窗口。

**建除值日**：建、除、满、平、定、执、破、危、成、收、开、闭等日值标签。这里只作实际字段展示，不另加一遍分数。

**日值神与时值神**：分别对应日项、时项的历书字段。保留原始神名和吉凶标签，不根据名字听起来吉祥就猜吉凶。

**上表章**：传统文书呈递事项；现代学术提交是本包的类比，不是古代期刊审稿规则。

**时窗**：真正可用的操作区间。基于北京时间传统时段切分，再按当地09:00—21:00和现实限制裁切。带分钟的边界可能来自时区或截止，不等于分钟级占卜。

**取象分**：内部固定公式产生的排序指标。100分也不表示必定录用，0分也不表示拒稿。

## 三、其他问事在包内如何处理

先在 `../rules/submission-v1.json` 的 `events` 查本地映射。已有入口直接使用本地择时流程；没有直接古代代理项则明确采用通用日时取象，事件项中性，不让模型临时造代理。

问“哪天提交修回”时走 `revision`；问“哪天和合作者谈”时走 `meeting`；问具体概念时直接用本文件解释，不收集无关出生资料。

问“我五行怎么样”时，不根据专业、昵称或头像判断。可先了解是否有已确认四柱；没有实际数据时，使用 personal.py 在出生资料完整后实排四柱；缺失资料不猜补，也不声称已排盘。

问“这次能不能录用”时，不预言编辑决定。可说明已有窗口的取象依据，并把行动落在范围匹配、证据完整、作者确认和附件核对上。

问实验时，取象仅辅助准备、复核与记录安排。实验操作、培养维护、取样时点、用药与安全要求不因分数改变。

## 四、用户给出已有盘面

只解释用户实际提供、足够明确的内容。至少确认盘面日期时刻、时区、排法口径和具体字段；缺少的部分不猜补。

用户提供盘面可解释；投稿量化排序使用 personal.py 的实排四柱与 analysis-v2命盘与运势上下文规则，通书和个人栏目分分栏展示，不暗改分数。不能以“需要合参”为由调用另一套 Skill。

本版没有实现的算法就不假装完成。所有已支持功能由本目录直接处理，不需要外部命盘服务或额外知识 Skill。
