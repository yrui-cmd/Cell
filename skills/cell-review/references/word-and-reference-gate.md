# Word 与至少 30 篇文献的最终验收

## 唯一交付

`review.docx`（或实际综述标题命名的 `.docx`）是真正的可编辑 Word，不是 Markdown 改后缀、PDF 改后缀或图片塞进 Word。全部正文、参考文献与必要图表/方法附录同文保存。内部源稿 `_work/review.md`、日志、页面预览和审核报告不作为额外交付。

本 Skill 不自带文献下载器或 Word 渲染引擎。实际导出与逐页预览由宿主真实可用的 Word 工具执行；有内置 DOCX 技能先读取。可用 Python-docx、已安装的文档转换工具或宿主文档能力生成 Word，但不能声称运行了不存在的工具。没有相应能力时如实说明 Word 未完成，不用其他格式冒充。

## 数量计算

门槛是 **>=30 篇**真实、相关、实际阅读和核验、正文确实引用的独立文章；不是搜索结果数、PDF 文件数、引用出现次数或最大参考文献编号。参考文献列表必须与正文引用对应；在文章中承担背景、支持、反例或方法作用，不为计数堆入无关文献。

计数类型：`original_research`、`research_article`、`review`、`systematic_review`、`scoping_review`、`meta_analysis`、`methods_article`、`conference_paper`。会议论文限完整学术论文，不包括仅有摘要。一般网页、新闻、期刊作者指南、软件说明和 Skill 文件仍可在确有必要时引用，但不计入 30 篇。撤稿及发表状态不明的文章不计入门槛；预印本仅在范围允许、如实标明未同行评议时计入。原则上用原始研究支撑关键机制，不限制所有文章必须来自顶刊，也不强行设置原始研究/综述比例。

`article_id` 关联同一篇文章的预印本、正式版或其他版本；同一文章只计一次。`study_id` 关联同一研究/队列下不同文章。两篇实质不同的文章可以计两篇，但不等于两个独立研究。脚本交叉使用 article_id、规范化 DOI/稳定标识及标题去重；版本标题变化且标识符也变化时，需要宿主如实给出相同 article_id。程序无法从虚假字段重建真实身份。

计数文章还需有：真实筛选理由、相关性说明、metadata_check 核验、reading 阅读标记、至少一条指向正文实际主张的已核验 links 和原文定位。只读摘要时只能用于摘要能支撑的有限表述；复杂机制、数值和因果结论仍需相应全文、图或补充材料。计数脚本不替宿主确认这些记录的真实性。

数量不足时继续有方向地检索和核验；达到 30 篇后也不能因为达标而跳过主线及反证。确实不足时保留真实数量，交付只能标为 **Word 未完成稿**，说明未达到最低要求。禁止灌水、造假、降低门槛或偷换题目范围。

## 源稿、最终样式与引用对应

内部 `_work/review.md` 保持 `citation_style=numeric_draft`，正文用 `[1]`、`[1,2]`、`[1–3]`，每条书目以 `[1]` 起始，参考文献二级标题为 `参考文献` 或 `References`。

最终 Word 默认 `output_citation_style=numeric`，保持相同标号，书目使用实际文本标号（不是只存在于自动编号设置里的不可提取数字）。Word 标题用真实段落样式，不显示 Markdown 的 `##`。目录不是必需的；避免将“参考文献”同时作为纯文本目录项，否则自动定位可能歧义。

已核实期刊要求作者—年份、裸上标等样式时，设置 `output_citation_style=custom`，在 `delivery_review.citation_map` 为每条引用记录实际最终稿中的片段：

```json
{
  "ref_id": "R001",
  "marker": "实际引文标记",
  "body_excerpt": "Word 正文实际存在的完整主张句及引文标记",
  "reference_excerpt": "Word 文末实际存在且含完整文章标题的一条书目"
}
```

这些只是字段说明，不是真实文章。引用片段必须包括登记在 claims 中且由该文章支撑的实际文字。程序对照当前 Word 的文本检查，不接受写着“已核验”却找不到对应文字的映射。最终格式确实省略标题时可保留标题的 Word 审阅稿；不能假称不受支持的格式已自动验证。

## Word 排版与复核

使用目标期刊已核实的版式；未指定时用克制的学术排版（标准纸张与页边距、清晰标题层级、统一正文/书目样式、页码）。中英文使用支持对应字符的字体；无法安装字体时合规替代并检查字符，不附送字体文件。不添加装饰封面、说明书或大段任务介绍。

生成 Word 后必须：

1. 对照源稿核查完整正文、引用、表格、图注、特殊字符和必要附录，没有漏文或错序。
2. 实际渲染或逐页预览，检查所有页面；确认无乱码、截断、重叠、孤立标题或异常空白页。
3. 修改后重新预览，最终填写 `delivery_review` 的真实时间、页面数、检查页数、实际预览定位和 checks。
4. 用 `review_tools.py hash` 获取当前 `_work/review.md` 和 Word 的哈希，分别填写 source_sha256 和 docx_sha256。不要手工伪造或让脚本直接把未做的检查设为 true。

本地命令：

```bash
python "<skill_dir>/scripts/review_tools.py" audit "<run_dir>"
python "<skill_dir>/scripts/delivery_gate.py" "<run_dir>"
```

第二个命令重读实际 DOCX，以正文—书目—台账的对应关系统计有效文章数，并检查身份分组、自查和哈希。第一步即使返回 `RECORDS_CONSISTENT`，也不代表可以交付。只有第二步满足所有条件才返回 `DELIVERY_CHECKS_PASSED`；其含义仍只是结构与宿主记录一致，不是科学正确、真正看过页面或达到期刊录用标准的独立认证。

未具备本地执行能力时必须通过等价的真实文件阅读、逐条计数和逐页检查执行相同门槛，并说明未运行脚本；不能因为没有脚本就免除 Word 和 30 篇要求。
