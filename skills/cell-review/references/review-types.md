# 综述类型与诚实边界

默认是 `critical_narrative`。这个 Skill 不因为用了可追溯检索就自动获得“系统综述”资格。

## critical_narrative：批判性叙述综述

围绕机制、解释或问题综合证据；保留检索和选择说明，重点是清晰问题、质量判断、矛盾和适用边界。没有系统综述完整工作流时，不展示虚构 PRISMA 流程，不声称穷尽或无遗漏。

## scoping：范围综述

用户明确要求时，先确定目的、范围框架、方案与适用方法指引，按真实检索、选择和证据制图过程工作。使用适用的范围综述报告指引；质量评价是否开展按目的与方案说明，不能一概视为必需或一概省略。

没有完成的流程直接披露；不能把几篇代表性文献的领域介绍命名为完成的范围综述。

## systematic：系统综述

先查阅与领域、设计和问题匹配的当前方法手册与报告指引。PRISMA 是报告规范，不是完成方法学步骤或质量认证的替代物。

保存方案、纳入排除条件、可复现的数据库专用检索式、全部实际检索与筛选计数、全文排除理由、数据提取、适用的偏倚评价、合成方法与限制。流程图数字来自真实记录，并区分 records / reports / studies；没有数字不能用估计补齐。

双人独立筛选、提取或复核按照采用的方法要求安排。单宿主多轮自查不是两名独立研究者，也不能记录不存在的共识会议或评审人。能力不够时记录实际流程和偏离，只交付明确的方法未完成稿，不伪称符合完整标准。

注册只在确有注册记录时声明。写出一个方案文件不等于已注册；本 Skill 不自动向外部平台注册。

## meta_analysis：Meta 分析

首先满足适用的系统综述要求；再判断是否可合并，选择合适效应量、统计模型、研究单位、依赖性处理、异质性和敏感性方法。不得把不同指标、重复队列或不同随访窗口机械合并。

统计运算由经核验的本地代码或宿主统计工具完成，保留真实输入与可复现输出，不能由语言模型凭空写合并效应或森林图数字。当前 Skill 不包含一个可自动适用于所有设计的 Meta 分析引擎。

无法可靠完成统计时，交付明确标注“未完成定量合成”的完整叙述性结果稿与所缺信息；不得把它作为已完成 Meta 分析。

## 正式类型的状态记录

`protocol.formal_methods` 记录适用指南、方案状态、真实筛选与复核设置、计数、偏倚评价、综合与统计执行情况和未完成事项。没有完成时 `completed=false`。只有宿主核查实际过程后才能改为 true；本地脚本只能核对记录，不能替你判定方法充分。
